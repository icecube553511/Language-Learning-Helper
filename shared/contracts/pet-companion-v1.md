# 冰子宠物交互契约 v1

`pet-companion-v1` 定义 LexiTrack 的跨端陪伴宠物语义。冰子是只存在于
presentation 的瞬态 UI 状态，不写入词库、学习进度、设置或任何持久化文件。

## 身份与资源

- 名称：`冰子`
- 原始源图：`shared/assets/branding/pet_image.png`
- 右向运行资源：`shared/assets/pets/bingzi.png`
- 左向运行资源：`shared/assets/pets/bingzi-left.png`
- 运行资源是由 `tools/prepare_pet_asset.py` 从原始源图生成的透明 PNG，平台
  只能加载运行资源，不应让 domain/application 读取图片文件。左向资源必须是
  右向资源的逐像素水平镜像。

## 目标区域

presentation 可将当前页面的几何区域注册为以下类型：

- `control`：按钮、选项框、搜索栏、导航项等可点击控件
- `surface`：卡片、面板和边框
- `chart`：图表边界和曲线
- `edge`：窗口或屏幕的左、右竖直边和下边；顶边的上侧在可视区域外，不能注册

注册区域使用屏幕坐标、稳定 id 和 `[x, y, width, height]` 矩形边界。
宠物尺寸参数表示从中心到边界的半尺寸。可见的按钮、输入框、选项框、
滑块、数字输入框、列表、滚动条和导航项必须各自注册为 `control`；禁用但
仍可见的控件仍可作为停留边界。不可见、尺寸为零、被滚动/祖先容器裁剪或
位于当前页面之外的区域不得作为目标。普通文字标签不要求单独注册。

应用自有的 Dialog 和 Toplevel 使用各自独立的坐标系、目标注册表与宠物
overlay，其中的可见控件和边框遵循相同注册规则。同一时刻只显示一只冰子：
最上层宠物宿主窗口激活时隐藏下层 overlay，关闭后恢复上一层。系统文件选择器、
系统消息框、通知栏等由平台进程托管且应用无法覆盖的 UI 不属于本契约目标范围。

单词气泡是宿主窗口上的临时信息层，不是新的宠物宿主，不能创建另一只冰子、
接管宠物状态或把宠物约束在气泡本地视口。气泡打开后，冰子继续使用触发点击
所在宿主的视口和目标注册表，因此可以被拖到气泡之外，也可以自行移动到气泡
之外。即使在最小宿主或最大字号下，气泡布局也必须为一个完整显示尺寸的冰子
保留可达通道；主窗口中的气泡保留主窗口冰子，学习提醒中的气泡保留提醒窗口冰子。
气泡仍必须保留视觉 owner 链：从学习提醒中打开的气泡属于提醒窗口，从已有
气泡中递归打开的子气泡属于该气泡，不得回退绑定到主窗口。owner 被销毁时，
其子气泡必须同步清理，不得留下陈旧气泡栈或阻止同一单词再次打开。

学习提醒本身是宠物宿主：出现时必须在提醒窗口中恰好显示一只冰子，并隐藏
主窗口或其他下层宿主的 overlay；提醒关闭后恢复先前活动宿主中的宠物。宿主
窗口顺序按真实的 focus/map/Z-order 更新；宿主发生 `unmap` 或 `destroy` 后从
活动栈移除，并恢复仍处于 mapped 状态的下一层宿主，不得留下无宠物或多只
宠物的中间状态。Windows 的置顶提醒及其宠物 overlay 必须处于同一 topmost
层级，且宠物实际位于提醒窗口之上，不能只满足 mapped/viewable 状态。

普通矩形目标只把扩展半尺寸后的上边缘作为承载面，冰子的底部接触该边缘，
不得沿矩形下边缘行动。窗口下边同样只使用上侧承载面；chart 折线路径按宠物
半尺寸向上偏移，使冰子始终位于曲线上方；竖直屏幕边缘仍可沿线移动。日常
自动漫游的目标选择先考虑当前位置距离，再以屏幕中心距离加权，并惩罚屏幕
边缘目标，使冰子更频繁地活动在中心附近；同分时按注册顺序稳定决策。切页后
的导航项和窗口边缘仍可参与选择，但 `fall` 不使用中心偏好：只允许选择下方
最近的承载面，不得选择当前位置上方的目标。`fall` 是纯竖直运动，宠物中心的
`x` 不得改变；候选承载面的实际几何必须与 `x = currentX` 的竖直射线相交。
矩形要求扩展宠物半尺寸后的承载面满足
`support.left <= currentX <= support.right`，chart 要求偏移后的曲线路径本身存在
该射线交点。水平错开的目标即使纵向更近也不合法，必须继续选择更低的合法交点，且
不得转成 `fly` 横移。没有合法下方目标时继续下落到活动窗口视口下边缘形成的
合成承载面，其中心纵坐标为 `viewport.bottom - petHalfSize`。`fall` 的目标不是
一次性锁定：每个 tick 都必须按当前几何重新选择上述竖直射线下最近的承载面。
若下落途中出现一个比旧目标更近的新承载面，必须改以新承载面作为本 tick 的
最早碰撞候选，不能穿透它继续落向旧目标。

## 行为

在没有用户拖动时，冰子以约 `16 ms` 的 tick 频率自动行动。除既有
`idle`、`slide`、`roll`、`fly`、`fall`、`bounce`、`dragging` 外，甩出时使用
瞬态 `fling` 模式；其状态只存在于 presentation/domain reducer，不进入持久化：

1. 可以在控件/面板的上承载面往返行动、沿竖直屏幕边缘移动，并在 `chart`
   的记忆曲线上方滑行；
2. 可以在屏幕边缘或任意注册区域上短暂停留；
3. 目标不在同一条边界上时，沿竖直方向飞行到最近目标；
4. 页面导航发生时，先从当前位置受重力加速掉落到新页面最近的可交互区域；
   `fall` 期间纵坐标不得减小；没有合法目标时落到活动视口的合成下边承载面；
   达到重落地阈值时在落点原地衰减弹跳两次，再恢复自动行动；
5. 用户按下冰子并拖动时立即进入 `dragging`；presentation 保留按下点相对
   宠物中心的抓取偏移，宠物中心随指针位移并限制在窗口内，不得在按下时
   瞬移到指针中心；
6. 用户释放指针后保留当时经过窗口约束的宠物中心位置；若位于合法承载面上，
   进入 `idle`，若仍悬空，则清空目标、将向下速度重置为 `0` 并进入 `fall`。

`fall` 使用固定 `dt = 0.016 s`、向下为正的匀加速运动。重力为
`2148.4375` 逻辑单位/秒平方，速度单位为逻辑单位/秒，不设置最大下落速度。
每 tick 必须由 tick 起点的 `y0` 和 `v0` 使用闭式公式计算：
`dy = v0 * dt + 0.5 * g * dt^2`、`v1 = v0 + g * dt`。重落地阈值为
`437.5` 逻辑单位/秒，首次弹跳速度为 `312.5` 逻辑单位/秒；这些值分别等价于
旧的 `7` 与 `5` 逻辑单位/tick，但所有下落判断均使用秒制单位。

若一个 tick 内越过承载面，实现必须求解该 tick 内最早的连续碰撞时刻
`t_hit`，把位置钳制到交点，并使用真实触地速度
`v_hit = v0 + g * t_hit = sqrt(v0^2 + 2 * g * deltaY)` 判断是否达到重落地
阈值。视口下边的合成承载面与普通目标使用完全相同的判定：硬着陆进入
`bounce`、在原地以首次向上速度衰减弹跳两次；非硬着陆才进入 `idle`，不得因
它是合成目标而直接进入 `idle`。

普通移动使用加速与接近目标时的减速，避免速度突变。显示尺寸为 `112` 个平台
逻辑单位；自动移动的水平分量向左时显示左向镜像，向右时显示右向资源，纯
竖直移动保留最近朝向。

- 沿 `chart` 记忆曲线滑行同样使用缓慢加速和接近端点时的制动。曲线加速率由
  `motion.curveAcceleration` 给出（单位为逻辑单位/tick²），不得在首次命中曲线时
  突然跳到巡航速度。该加速率恒为 `0.25`，不得根据调用层传入的 `step`、预算上限
  或最大速度切换到普通移动加速度；例如当前速度为 `3.75`、调用 `step=30` 时，
  下一 tick 的速度仍只能是 `4.0`。曲线折线每个 tick 的运动预算应先按该加速率
  更新，再沿路径连续消费，跨越折点时保留剩余预算；若到折点还剩 `3.8`，必须在
  同一 tick 继续消费这 `3.8`，不得归零、重新加速或等到下一 tick。
- `fall`、`fling` 或无甩出速度的拖放首次落到 `chart` 时，必须以落点所在的连续
  折线段为准，不能先吸附到最近的离散采样顶点。以曲线注册顺序定义局部单位切线
  `T`，以触地世界速度 `V_hit=(vx, vy)` 计算有符号切向速度
  `u0=clamp(dot(V_hit,T)*dt,-8,8)`，单位为逻辑单位/tick；普通竖直下落的 `vx=0`，
  `fling` 使用连续碰撞时刻的二维速度。方向判断统一使用
  `motion.curveDirectionEpsilon=0.000001`：若 `abs(u0)` 不超过该阈值，必须先将
  `u0` 规范化为零；否则其符号决定初始方向，因此用户确实向上投掷时允许先上滑。
  `u0` 为零时必须选择使屏幕 y 增大的局部下坡方向，不得用“最近顶点”制造无外力
  上滑。
- 非 hard 的曲线触地直接进入 `slide`，并以有符号切向速度逐 tick 逼近本段的下坡
  终端速度；hard landing 仍按真实触地速度阈值进入 `bounce`。下坡方向同样使用
  `motion.curveDirectionEpsilon` 判断：`T.y` 大于阈值时取注册方向，小于负阈值时
  取反方向；绝对值不超过阈值的水平段固定沿曲线注册方向 `+1`，不得沿用旧的
  `pathDirection`。终端速度为
  `u_terminal=downhillDirection*4`。更新公式固定为
  `u_next=u+(u_terminal-u)*0.0625`；从静止开始的首 tick 增量仍为 `0.25`，随后速度
  越接近终端值，加速度越小并平滑趋近 `0`。该响应率、`4` 的终端速度和 `8` 的
  触地速度上限均不得受调用层 `step` 改写。若初速度朝上，公式应先减速、再过零并
  转为下滑。速度更新后的绝对值作为当 tick 沿折线连续消费的弧长预算，折点不得
  丢失剩余预算；到达上坡端点时从静止转向下坡，到达下坡端点后结束本次曲线滑行。
- 拖拽期间 presentation 必须保留带单调时间戳的指针样本。释放时用最近
  `drag.releaseVelocitySampleWindowMs` 内的末端切线（稳健线性回归或等价的加权
  末端差分）计算二维速度，单位为逻辑单位/秒；样本不足或速度低于阈值时使用零
  速度。样本必须来自窗口边界约束后的实际宠物中心，不能使用未约束的指针坐标。
  速度超过 `drag.maxFlingSpeed` 时按向量长度等比限幅。若速度非零，释放进入
  `fling`，保留 `velocity.x` 和 `velocity.y`；向下为正，重力沿 y 轴正方向，使用
  `dy = vy*dt + 0.5*g*dt²`、`vy1 = vy + g*dt` 的闭式积分。上抛时允许 `vy < 0`，
  在上升阶段不会被普通承载面吸附；下降穿过承载面时求 tick 内最早碰撞时刻并沿
  现有硬着陆/衰减弹跳规则处理。水平边界碰撞使用
  `motion.flingHorizontalRestitution` 反射，反射后的速度仍受限幅；竖直屏幕边缘
  可继续作为目标移动。
- `chart` 斜线段的连续碰撞必须使用相对曲线的接触方程。若线段为
  `y=m*x+q`，则求 `F(t)=y(t)-m*x(t)-q=0`，只接受
  `F'(t)=vy(t)-m*vx >= 0` 的最早有效根。不能只用世界坐标的 `vy(t)` 判断下降；
  宠物即使仍在向上运动，也可能相对一条下降斜线正在向下穿越并应当落地。
- 为避免高速状态在 16 ms 采样之间跳跃，模拟 tick 仍固定为 `tickMs`，但当速度
  或位移超过阈值时必须拆成不超过 `motion.maxSubstepSeconds` 的确定性子步（最多
  `motion.maxSubstepsPerTick` 个）。每个子步都执行同一闭式积分和最早碰撞检测，
  最终状态与等时长积分一致；渲染层可在相邻模拟状态之间插值，不得改变领域状态。
- 弹跳只改变竖直位置，不产生横向漂移（`fling` 的水平速度除外）。

## 拖拽甩出与跨窗口迁移

应用自有窗口是可互相进入的连续舞台。当前宠物宿主的可视口边缘不再是不可穿越
的硬夹具：当宠物中心沿左、右边缘越过完整显示尺寸，presentation 应在同一进程中
选择几何上相邻且已 mapped/viewable 的应用窗口，并把位置按边缘法线映射到目标窗口
内侧，保留切向速度、竖直速度、朝向和当前模式。候选窗口按实际屏幕矩形与运动
射线的最早交点排序，同分按宿主注册顺序；没有相邻窗口时仍使用当前宿主的视口边界。
有窗口间隙时必须把屏幕坐标轨迹写成 `p(t)=p0+v*t`，在本次 lookahead 内对候选
矩形做连续 ray/AABB 求交，按最小非负进入时间选择。仅因候选与源窗口在横轴或纵轴
投影重叠并不构成命中；射线没有穿过候选矩形时必须拒绝，不能把源边缘交点直接投影
或钳制进该窗口。

- 左右进入：`entryDirection` 为 `left` 或 `right`，位置从目标窗口对应的内侧边缘
  进入，水平速度分量保持符号并继续运动。
- 上方进入：从目标窗口顶边上方进入，模式强制为 `fall`，保留 x 和向下速度；若
  进入时带有向上速度，先完成抛体上升再受重力下落。
- 拖拽进入：用户按住冰子跨越窗口边界时立即迁移，保留抓取偏移和 `dragging`
  模式；松开后再按末端切线速度决定 `idle`、`fall` 或 `fling`。

自动迁移的候选窗口必须在运动方向上与当前宿主形成非负间距；仅仅覆盖当前
宿主的模态窗口不能被后台 tick 当作相邻窗口，否则会在窗口生命周期切换时抢走
宠物。显式拖拽跨窗时可以选择覆盖窗口作为目标，只要目标已 mapped/viewable，
并且仍然只显示一个宠物 overlay。

迁移是瞬态 presentation 状态，不写入持久化；同一时刻仍只有一个宠物 overlay。
迁移过程中必须使用完整显示尺寸作为边缘余量，不能出现半个 sprite 被裁切或在两个
宿主各渲染一只冰子的中间状态。窗口关闭、unmap 或不可见时立即取消其候选资格，
若宠物已经在其中则沿原运动方向迁移到下一候选窗口，否则回退到当前宿主视口。
曲线目标及其有符号切向速度属于原宿主的局部几何状态；迁移到新宿主时必须清空，
不得把原曲线速度套用到新宿主中同名或相邻的曲线。

实现可以使用不同的 easing 或姿态，但不得改变上述状态转换、命中范围和
拖放语义。宠物本身的命中区域应稳定，不因标签或动画帧改变尺寸。
